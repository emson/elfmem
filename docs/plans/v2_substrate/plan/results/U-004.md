## Missing context

**One real correctness catch made during implementation, not left implicit:**
the plan doc's framing ("migrate `self/constitutional` tag → `pinned: true`")
read at first like a replacement, but `context/frames.py`'s `SELF_FRAME`
still filters by `tag_patterns=["self/%"]` today and isn't touched by this
unit. Stripping the tag on export would have silently broken `frame('self',
...)` for every migrated constitutional block the moment export ran — before
any of the later units that migrate retrieval itself even exist. Fixed:
`pinned: true` is now additive, the tag stays. Worth double-checking this
stays correct if/when the retrieval-side migration (not yet an owned unit —
see U-002's flagged frame() gap) eventually changes how `self/%` tags are
read.

Two scope decisions, both consistent with the plan doc, not deviations:

1. **The row's existing `id` column is reused directly** as the permanent
   frontmatter `id:` rather than recomputed — it's already stable (content-
   hash- or uuid-derived at creation), and recomputing risks a fresh
   collision with an unrelated existing id that the original never had.
2. **`confidence`/`alpha`/`beta` land in `Block.extra`**, not as first-class
   frontmatter fields — U-001's schema is deliberately open for exactly this
   case, and adding fixed fields to the base schema for migration-only data
   would grow it for every future block, not just migrated ones.
