## Missing context

**A real design bug found only by running the tests, not by reasoning about
it beforehand** — worth stating plainly since it contradicts what the
`/simulate` resolution in `model.md` implied without spelling out this
consequence: the original plan (all of a peer's messages appended into one
shared `log/peer-YYYY-MM.md` file, matching the `learn()` log convention)
collides with U-001's own duplicate-`id:`-within-one-file invariant. A block's
`id:` is content-hash-derived; the exact scenario this unit exists to fix —
two *distinct* messages sharing identical content — produces two blocks with
the *same* `id:` landing in the *same* file, and U-001's parser correctly
raises `BlockFileError` rather than silently letting one shadow the other.

**Fixed by landing each message in its own file**, named by
`<peer-slug>-<msg_id-slug>.md` under `log/peer/`. This is strictly better
than the shared-file design, not just a workaround: it makes the landing
path fully append-only at the *file* level too (no file is ever opened for
read-modify-write), which improves the concurrency story (P3 in the
`/simulate` trace) beyond what was already claimed — two peers, or the same
peer sending twice in quick succession, never contend on one file.

This is the second time in this session a unit's actual build surfaced a
real interaction the plan hadn't spelled out (U-002 found the edge/frame()
gaps the same way). Recorded here rather than only in code comments, per the
constitution's "report missing context" rule — worth a look if a third
instance shows up, per model.md's own model-drift-log guidance ("repeated
entries mean the interpretation is wrong").

**Scope, confirmed as intentional, not an oversight**: export re-pointing
(reading from files instead of DB rows for `_build_bundle`) was not built —
flagged in `build-plan.md`'s Coverage table already, before this unit
started, as belonging to U-006/U-007 alongside the other live-path
