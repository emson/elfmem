## Missing context

**Contract was rescoped before implementation, not silently reinterpreted**
— documented in `build-plan.md`'s U-003 entry and its own "Revision note."
Summary: the original contract named `src/elfmem/api.py` as the unit to
re-point at files, but the live system is still DB-primary until migration
(U-004–U-006) completes. Re-pointing the actual public API now would split
"what the API returns" from "what's authoritative" mid-build. Built the
file-native primitive layer as an independent module instead; wiring it into
`MemorySystem` is now an explicit sub-task of U-006 (added to build-plan.md's
Coverage table).

One smaller decision: `list_blocks`' `category_subdir` filter takes the
literal subdirectory name (`"notes"` or `"log"`) rather than the existing
DB-native `category` column's vocabulary (`"knowledge"`, `"observation"`,
etc.) — those are different axes (file provenance vs. content classification)
and conflating them would have been the "inherits nothing" mistake this
whole redesign exists to avoid repeating.
