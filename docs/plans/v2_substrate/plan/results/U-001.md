## Post-hoc fix (2026-08-10, after a real-data migration dry run)

A real bug, not caught by any fixture in this file: `parse_blocks` treated
**every** `##` line as a block boundary. Real content routinely contains its
own markdown sub-headings — Theory-of-Mind blocks especially, with bodies
like `# Mind Model: X\n\n## Goals\n...\n\n## Beliefs\n...`. Running the
actual migration mechanism (U-004 export → U-002 rebuild → U-005 parity)
against a read-only copy of the real 185-block production database
surfaced this concretely: 15 blocks (the `mind` and `message` categories)
were mis-split into 158 blocks on rebuild.

**Fixed**: a `##` line only counts as a genuine boundary if either no block
has started yet, the block currently accumulating has no frontmatter of its
own (bare/hand-authored files — nothing to disambiguate against, so every
`##` still splits, preserving original behaviour for that case), or the
candidate line is itself immediately followed by a frontmatter comment.
Two new tests (`test_embedded_headings_stay_inside_the_block`,
`test_multiple_bare_blocks_still_split_correctly`) — the second exists
because the first fix attempt broke the bare-block case, caught by that
test before it shipped. Full detail: `docs/plans/v2_substrate/plan/dry_run_2026-08-10.md`.

**Why this wasn't caught earlier**: every fixture in this unit's original
test suite was hand-written to be minimal and well-formed by construction —
none happened to contain a block whose body used its own `##` sub-heading.
This is the value of testing against real data before Wave 5/6, not a
process failure — synthetic fixtures test what you thought to test; real
data tests what's actually there.

## Missing context

Two judgment calls the packet left implicit, recorded so they're visible
rather than silently baked in:

1. **"Byte-stable" round-trip was implemented as field-level dataclass
   equality after parse→write→parse**, not literal byte-for-byte text
   preservation. Exact text preservation would also require preserving
   insignificant whitespace/formatting choices the writer doesn't control
   (e.g. an author's original indentation), which isn't meaningful once the
   writer normalises formatting. Flagging in case a stricter interpretation
   was intended — nothing here is hard to change if so.
2. **Malformed-frontmatter recovery writes out *valid* frontmatter, not the
   original malformed text.** `write_blocks` always emits well-formed syntax,
   so `test_round_trip_malformed_frontmatter_block_survives` shows the block
   round-trips *clean* on its second write, not still-malformed. This seemed
   like the right behaviour (a `--check`/repair path, not a "preserve the
   bug" path) but is worth confirming against intent before U-002 builds on it.
